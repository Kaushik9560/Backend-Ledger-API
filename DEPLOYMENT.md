# SpendWise Deployment Guide (MongoDB Atlas + Render)

This repository is configured as one Docker web service: Express serves both the API and the built React app. Render reads `render.yaml`, builds `Dockerfile`, generates `JWT_SECRET`, and asks for `MONGO_URI` during first-time setup.

## 1. Local checks

Requirements: Node.js 22+, npm 10+, Docker (optional), and a MongoDB Atlas connection string.

```bash
cd backend-ledger
npm ci
npm test

cd ../ledger-frontend
npm ci
npm run build
```

All backend tests and the frontend build should pass before a deploy.

To test the production container locally:

```bash
cd ..
cp backend-ledger/.env.example backend-ledger/.env
openssl rand -base64 48
```

Put the generated value in `JWT_SECRET` and your Atlas URI in `MONGO_URI`, then run:

```bash
docker build -t spendwise .
docker run --rm --env-file backend-ledger/.env -p 3000:3000 spendwise
curl http://localhost:3000/api/health
```

Expected health response:

```json
{"status":"ok","service":"backend-ledger","database":"connected"}
```

Never commit `backend-ledger/.env`; it is already ignored by Git and Docker.

## 2. Create the MongoDB Atlas database

1. Create an Atlas project and a Free/Flex or dedicated cluster.
2. In **Database Access**, create a dedicated database user for this app. Give it only the access the app needs (for example, read/write access to the `spendwise` database).
3. Click **Connect > Drivers > Node.js** and copy the `mongodb+srv://...` URI.
4. Replace `<db_password>` and add `spendwise` as the database name:

   ```text
   mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/spendwise?retryWrites=true&w=majority&appName=SpendWise
   ```

5. URL-encode reserved characters in the username/password. Keep the final URI private.

Atlas accepts connections only from entries in its IP access list. The secure setup is to allow the Render service's outbound CIDR ranges:

1. Create the Render service in step 4 (its first DB connection may fail).
2. Open the Render service and select **Connect > Outbound**.
3. Copy every displayed CIDR range into Atlas **Network Access**.
4. Trigger **Manual Deploy > Deploy latest commit** in Render.

For a quick demo only, `0.0.0.0/0` works temporarily, but replace it with the Render outbound ranges afterward.

Official references: [Atlas driver connection](https://www.mongodb.com/docs/atlas/driver-connection/), [Atlas IP access list](https://www.mongodb.com/docs/atlas/security/add-ip-address-to-list/), [Render outbound IP ranges](https://render.com/docs/outbound-ip-addresses).

## 3. Push the project to GitHub or GitLab

This downloaded folder does not currently contain Git history. Create an empty remote repository, then run from the project root:

```bash
git init
git add .
git commit -m "Prepare SpendWise for deployment"
git branch -M main
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

Before pushing, run `git status` and confirm that `backend-ledger/.env` is not listed.

## 4. Deploy with the Render Blueprint

1. Sign in to Render and choose **New > Blueprint**.
2. Connect the repository from step 3.
3. Render detects the root `render.yaml`.
4. When prompted for `MONGO_URI`, paste the complete Atlas connection string.
5. Apply the Blueprint and wait for the Docker build and health check.
6. If Atlas rejects the first connection, complete the outbound-IP allowlist steps above and redeploy.
7. Open `https://YOUR-SERVICE.onrender.com/api/health`; it must return HTTP 200 with `database: "connected"`.
8. Open `https://YOUR-SERVICE.onrender.com` and test registration, login, account creation, income/expense creation, and transfer.

The Blueprint currently selects Render's Free plan and Singapore region. Free is suitable for demos, but [Render spins a Free web service down after 15 minutes without inbound traffic](https://render.com/docs/free). For a real always-on production workload, change `plan` in `render.yaml` to the paid instance type you want and review current Render pricing.

Official references: [Render Blueprint specification](https://render.com/docs/blueprint-spec), [Docker on Render](https://render.com/docs/docker), [Render health checks](https://render.com/docs/health-checks).

## 5. Environment variables

| Variable | Required | Production value |
| --- | --- | --- |
| `NODE_ENV` | Yes | `production` (already in `render.yaml`) |
| `MONGO_URI` | Yes | Atlas connection URI; secret, provided during Blueprint setup |
| `JWT_SECRET` | Yes | Random 32+ character secret; generated by Render |
| `EMAIL_ENABLED` | No | `false` unless Gmail OAuth is configured |
| `EMAIL_USER` | If email enabled | Gmail account |
| `CLIENT_ID` | If email enabled | OAuth client ID |
| `CLIENT_SECRET` | If email enabled | OAuth client secret |
| `REFRESH_TOKEN` | If email enabled | OAuth refresh token |
| `CORS_ORIGIN` | Separate frontend only | Comma-separated exact origins; leave unset for the bundled same-origin app |
| `COOKIE_SAME_SITE` | No | `lax` for bundled app; use `none` only for a separate HTTPS frontend |
| `AUTH_RETURN_TOKEN` | No | `false` keeps JWT out of browser-readable production responses |
| `API_RATE_LIMIT_MAX` | No | Requests per IP per 15 minutes; default `300` |
| `AUTH_RATE_LIMIT_MAX` | No | Failed auth requests per IP per 15 minutes; default `20` |

Do not set `VITE_API_BASE_URL` for this one-service deploy. The production frontend automatically calls its own origin.

## 6. Post-deploy checklist

- Health endpoint returns HTTP 200.
- Render logs show both `Server is connected to DB` and the listening port.
- Atlas database user is app-specific and its password is not reused.
- Atlas Network Access contains Render's outbound CIDRs, not an unnecessary public allow-all entry.
- HTTPS loads without mixed-content or CORS errors.
- Registration, login/logout, income, expense, delete/reversal, and transfer work.
- Set Atlas backup/alerting and Render monitoring appropriate to the chosen paid tier before storing important financial data.
- Rotate `JWT_SECRET` if it is ever exposed; existing sessions will be invalidated.

## 7. Common failures

| Symptom | Fix |
| --- | --- |
| `MONGO_URI is required` | Add the full URI in Render **Environment**. |
| `Unable to start server: ... selection timed out` | Check Atlas IP access list, database username/password, URI encoding, and cluster status. |
| `JWT_SECRET must be ... at least 32 characters` | Generate a strong value; do not use the example placeholder. |
| Health endpoint returns 503 | The process is running but MongoDB is disconnected; check Render and Atlas logs/config. |
| Browser shows CORS 403 | For a separate HTTPS frontend, add its exact origin to `CORS_ORIGIN` and set `COOKIE_SAME_SITE=none`. |
| Docker build cannot find frontend files | Run the build from the repository root, not from `backend-ledger/`. |
